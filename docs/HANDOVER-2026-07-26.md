## Start here: one regression I introduced

**The shoot button overflows the bottom of the camera screen.** My fault, from
the viewfinder fix.

`CameraGuide.tsx:848` — the root is:

```jsx
<div id="camera-guide-container" className="flex flex-col h-full bg-neutral-950 overflow-hidden relative">
```

Fixed height, `overflow-hidden`, nothing scrolls. I gave the viewfinder
`min-h-[52svh]` so it would stop being a letterbox strip — but with a rigid
parent, the chrome underneath (slot row, phase nav, shoot button, utility row,
hint panel) gets pushed past the fold and clipped.

**Fix:** make the region *below* the viewfinder scroll, rather than shrinking the
viewfinder again. Wrap everything after the preview in a
`flex-1 min-h-0 overflow-y-auto` container. `min-h-0` matters — a flex child
will not shrink below its content without it, which is the usual reason this
pattern silently fails.

Do not simply lower `min-h`. The viewfinder being too small is the complaint
that started this, and the two are not actually in conflict once the chrome
scrolls.

## What shipped today

### Pipeline: Lens → Flow → website

Was publishing invented specs. TruFlow's importer read
mileage/transmission/fuelType off the export and fell back to
`0 / "Automatic" / "Petrol"` — and TruLens never sent them, so the fallbacks were
what every dealer site published.

- TruLens now captures **mileage (required), transmission, fuel** and sends them
- **VIR score and per-section findings** now reach the feed (`vir`, `virReport`)
  — they had never left the app
- **Damage tagging ported from Inspect** — see below
- Feed also carries `walkaroundVideo` / `videoPoster`, split out of the photo
  arrays by MIME so a video can never again be published as a still

Proven on production: `3443214 km · Manual`, neither a default; `vir 92` with 2
report sections; photos 2 → 5 → 7 across three exports.

### Damage tagging (new in Lens)

`DamageTagger.tsx` ported from Inspect whole. Tap the exact spot on a real photo,
record panel / type / severity 1–5 / note, pinned to an x/y.

- Stored on `vehicle.damageFindings`, keyed by photo slot
- Persisted through the existing upsert — `POST /api/inventory` merges, so no new
  endpoint
- Published on the feed as `damage`, x/y intact
- **Only human-confirmed findings travel.** An AI suggestion starts
  `confirmed:false` and must be accepted by a person. Verified: of three tagged,
  the unconfirmed one is withheld.

This closes a loop that was already half-built — Caledon's `coc-media.js` has
always read `car.damage` and never had anything to read.

### Capture UI

- Removed the **"Lighting Perfect" pill and level bubble**. Neither measured
  anything: roll/pitch came from `simRoll`/`simPitch` — simulator state — and the
  lighting verdict was a fixed string. They reported confidence the app did not
  have, on top of the one region that must stay readable.
- **Slot chips no longer crush.** The row was `overflow-x-auto` but the chips had
  no `shrink-0`, so flex compressed them and `whitespace-nowrap` pushed each
  label onto its neighbour.
- **Failed saves are now visible.** `handleSaveProcessedImage` cleared the
  pending shot *before* uploading and on failure set a flag and nothing else — so
  losing a shot looked identical to keeping one. This is why four consecutive 360
  exports appeared to succeed while the video never left the phone.
- Renamed the 360 to **Tru Orbit** across Lens, Inspect and Caledon. Copy only —
  the data contract (`walkaroundVideo`, `video_360`, `spinImages`) is untouched
  because MKR's site already probes those names.

### Caledon's website

- **Restored three files** that were referenced by `index.html` but existed only
  inside the old deploy zip: `coc-skin.css` (30 713 b — a third of the site's
  CSS), `coc-splash-v2.jpg`, `coc-splash-v2.mp4`. A redeploy would have shipped a
  visibly broken site.
- **Apex domain does not resolve.** `carsoncaledon.co.za` has an SOA record and
  nothing else — no A, no CNAME; only `www` resolves. Every canonical and
  `og:image` pointed at the apex, so **share cards were rendering blank** on a
  site whose every CTA is a `wa.me` link. Now `www` throughout. Add an apex DNS
  record if you want the bare domain to work.
- **Removed another dealer's pages.** `truchat/ray/*` (Your Car Guy,
  083 465 9921) and `truchat/true-cars/*` (+27 62 050 2091) were publicly served
  and indexable on his domain. They could not simply be deleted because
  `index.html` loaded true-cars' widget through a global alias — Caledon now has
  his own `truchat/coc/widget.js`. ~700KB gone; `robots.txt` disallows
  `/truchat/`.
- **No more invented stock.** `MOCK_STOCK` was 8 fabricated cars with stock
  photography, shown whenever the feed failed and still captioned "8 vehicles in
  stock". Removed. **House standard added: the showroom holds below 5 cars**, and
  the splash holds as the front door with it — but stays dismissible, because
  trade-in, finance and WhatsApp all work with no stock.
- Body types normalised (`Bakkie / Truck` → `Bakkie`) and chips derived from real
  stock; `coc-book.js` no longer stamps calendar invites `@mkrautosales.co.za`;
  `tru-afford.js` no longer falls back to another dealer's WhatsApp number.

**Deploy zip rebuilt** — `cars-at-caledon-DEPLOY.zip`, 1.14MB (was 1.76MB).
Rollback preserved as `cars-at-caledon-DEPLOY-ROLLBACK-20260724.zip`.
**Not yet deployed to Netlify.**

## Codes — the state of truth

Two systems that never check each other. A dealer needs both.

| | Lens (phones) | Flow (dashboard) |
|---|---|---|
| Stored | `TRULENS_DEALER_CODES` env var on `trusaas-lens`, plaintext | hashed in `/var/data/auth.json` |
| Readable later | yes | **no — shown once** |
| Get it wrong | **cars land on another dealer's website, silently, with a 201** | he just cannot log in |

- **Master admin (Flow):** held, verified.
- **Lance / Cars on Caledon:** `LANCE45456` — verified on **both**. Pins to
  `cars-on-caledon` in Lens, signs in as `d2 / principal` in Flow.
- **MKR:** Flow code held. Lens code in Render, not yet verified.
- **Demo:** no code needed — `POST /api/auth/demo` opens the sandbox without one.

**Rotating a Flow code silently invalidates whatever you wrote down.** That is
what happened to `LANCE45456` earlier — it read as "Invalid code", identical to a
typo.

### Three identifiers per dealer, only one secret

| | MKR | Caledon |
|---|---|---|
| `id` (internal, on vehicles) | `d1` | `d2` |
| `slug` (public, feed URL + Lens pinning) | `mkr-autosales` | `cars-on-caledon` |
| code (secret) | — | `LANCE45456` |

The slug can never change — `PUT /api/dealerships/:id` refuses to edit it,
because vehicles are tagged by `id` and websites are wired to `slug`.
